# Module 4: AI Intelligence & Facility Care Level Recommendation

## 1. Overview
The AI Intelligence & Facility Care Level Recommendation Module (`com.ruralhealthcare.ai`) provides clinical decision support, symptom-based disease screening, risk stratification, and backend facility matching orchestration. It coordinates between patient clinical records, external machine learning screening models, and the local PostGIS facility database.

---

## 2. Core Architecture & Medical Safety Boundaries

```
Patient (Demographics: Age, Gender)
   ↓
Healthcare Case (Case ID, Coordinates)
   ↓
Symptoms (Recorded Clinical Evidence)
   ↓
POST /api/v1/cases/{caseId}/ai-analysis
   ↓
AiProcessingService (com.ruralhealthcare.ai.service.AiProcessingService)
   ↓
AiPredictionClient (Mock or External RestClient)
   ↓
External AI Model Clinical Result
   ├── Possible Disease Categories & Probabilities
   ├── Risk Score & Level (LOW, MODERATE, HIGH, CRITICAL)
   ├── Urgency Assessment (ROUTINE, PRIORITY, URGENT, EMERGENCY)
   ├── Clinical Precautions
   ├── Recommended Medical Services (MedicalServiceCode)
   ├── Recommended Primary Facility Type (FacilityType)
   └── Required Facility Types (Set<FacilityType>)
             ↓
      Spring Boot Backend Orchestrator
             ↓
      FacilityQueryService (Module 1 - Facility Management)
             ↓
      PostGIS Geospatial Facility Database
             ↓
      Filter & Rank:
        - Within Search Radius (e.g. 50 km)
        - isOperational = true
        - Satisfies Recommended Medical Services
        - Satisfies Required Facility Types
             ↓
      recommendedFacilities (Generated by Spring Boot)
             ↓
      Combined Public Response
```

### Critical Domain Boundaries:
1. **Clinical Responsibility Only in AI**: The external AI model evaluates clinical determinations (`riskAssessment`, `possibleDiseases`, `precautions`, `recommendedServices`, `requiredFacilityTypes`, `urgency`). The AI model never receives, calculates, or selects hospital records, coordinates, or facility IDs.
2. **Backend Orchestrates Facilities**: The Spring Boot backend uses `FacilityQueryService` to query real facilities from the PostGIS database based on the AI's clinical requirements, filtering for operational status, required services, and facility types.
3. **Dynamic Resolution on GET**: When `GET /api/v1/cases/{caseId}/ai-analysis` is called, `recommendedFacilities` are dynamically re-calculated from the live facility catalog.
4. **Missing Coordinates Resilience**: If patient/case coordinates are missing or invalid, AI clinical analysis still succeeds, returning `recommendedFacilities = []` and `facilityMatchingNote = "Facility matching unavailable: patient/case coordinates are missing or invalid."`.
5. **PII Sanitization**: Only clinical symptoms, patient age, and gender are transmitted to the AI client. PII such as full names, contact numbers, and addresses are excluded.

## 4. Configuration Properties

Configured in [`application.yml`](file:///d:/mit-india/Grand-Finale/src/main/resources/application.yml):

```yaml
ai:
  model:
    provider: ${AI_MODEL_PROVIDER:mock}             # "mock" or "external"
    base-url: ${AI_MODEL_BASE_URL:http://localhost:9000}
    predict-path: ${AI_MODEL_PREDICT_PATH:/predict}
    api-key: ${AI_MODEL_API_KEY:}
    version: ${AI_MODEL_VERSION:health-model-v1}
    connect-timeout-ms: ${AI_CONNECT_TIMEOUT_MS:5000}
    read-timeout-ms: ${AI_READ_TIMEOUT_MS:15000}
```

## 5. Endpoints

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `POST` | `/api/v1/cases/{caseId}/ai-analysis` | Aggregates symptoms, calls clinical AI model, orchestrates facility search via `FacilityQueryService`, and returns combined response. |
| `GET` | `/api/v1/cases/{caseId}/ai-analysis` | Retrieves stored clinical result and dynamically recalculates current facility recommendations. |
